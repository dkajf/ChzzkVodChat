## Bug Report - TC_v2.0_001

### Summary

옵션 탭에서 마우스 휠 스크롤이 실제 옵션 영역의 경계를 넘어 빈 공간까지 이동하는 문제.

### Environment

- version : v2.0 GUI, 옵션별 설명 추가 이후 수정 전 빌드
- OS : Windows
- 발생 화면 : 옵션 탭
- 입력 방식 : 마우스 휠
- 보고서 작성일 : 2026-11-11

### Severity

Minor

옵션 화면의 이동 범위와 사용성을 해치는 UI 오류.

### Priority

Medium

### Discovery Context

- UI를 확인하기 위해 수집·분석 → 채팅 분석 → 옵션 탭을 순서대로 확인했다.
- 탭 전환과 각 화면의 배치를 확인할 때는 특별한 이상이 보이지 않았다.
- 그러나 옵션 탭에서 마우스 휠을 사용했을 때, 옵션 내용의 끝에 도달해도 스크롤이 멈추지 않고 경계를 넘어 이동했다.
- 탭별 화면 표시 확인만으로는 발견되지 않았으며, 실제 휠 조작 과정에서 드러난 문제다.
- 탭 전환 순서는 당시 확인 과정이며, 특정 순서로 전환해야만 발생하는지는 확인되지 않았다.

### Reproduction Steps

1. 옵션별 설명이 추가된 v2.0 GUI 프로그램을 실행한다.
2. 수집·분석, 채팅 분석, 옵션 탭을 순서대로 열어 화면을 확인한다.
3. 옵션 탭의 설정 목록 위에서 마우스 휠을 아래 방향으로 돌린다.
4. 마지막 옵션이 보이는 위치에 도달한 후에도 휠을 계속 돌린다.
5. 실제 옵션 내용의 끝과 화면의 이동 범위를 비교한다.

### Expected Result

- 마지막 옵션과 설명이 보이는 위치까지만 스크롤된다.
- 내용 아래의 불필요한 빈 공간까지 계속 이동하지 않는다.
- 위쪽에서도 첫 옵션 이전으로 이동하지 않는다.
- 창 크기나 설명의 줄바꿈으로 내용 높이가 바뀌면 스크롤 경계도 현재 내용에 맞게 갱신된다.
- 내용이 화면보다 짧으면 불필요하게 스크롤되지 않는다.

### Actual Result

- 옵션 목록의 경계를 무시하고 휠 스크롤이 계속 적용됐다.
- 실제 옵션이 없는 아래쪽 빈 공간까지 이동할 수 있었다.
- 탭 전환과 초기 화면 배치가 정상으로 보여도 스크롤 경계는 정상적으로 동작하지 않았다.

### Investigation

- 수정 과정의 GUI 검사에서 현재 내용 높이와 스크롤 영역의 높이가 일치하지 않는 상태를 확인했다.
- 당시 검사값은 실제 내용 높이 660px, 스크롤 영역 높이 795px로, 이전 레이아웃의 높이가 이동 범위에 남아 있었다.
- 화면 표시 여부와 별도로, 레이아웃 변경 후 실제 내용 높이와 스크롤 경계가 일치하는지 확인할 필요가 있었다.

### Fix

- 스크롤 범위를 오래된 캔버스 영역 대신 현재 내용 위젯의 실제 높이로 계산하도록 수정했다.
- 내용과 표시 영역의 크기가 바뀌면 스크롤 영역을 갱신한다.
- 휠 입력 시 현재 이동 범위를 다시 확인하고 상·하한 안으로 이동을 제한한다.
- 내용이 표시 영역보다 짧으면 원점에 제한한다.

### Status and Verification

- 상태 : 수정 반영, 변경 범위의 GUI 검사 통과.
- 당시 관련 변경 사항을 묶은 단일 Tk GUI 테스트에서 위·아래 방향으로 각각 반복 휠 입력을 적용해 경계를 확인했다.
- 해당 수정 후 전체 회귀 테스트는 재실행하지 않았다.
- 이 보고서 작성 시 프로그램을 새로 실행하거나 재현 검사를 추가로 수행하지는 않았다.

### Regression Checks

- 옵션 목록의 맨 위·맨 아래에서 같은 방향으로 휠을 반복해도 경계를 넘지 않는지 확인한다.
- 탭을 전환한 뒤에도 같은 경계가 유지되는지 확인한다.
- 창 크기와 설명 줄바꿈이 달라진 뒤에도 내용 끝과 스크롤 끝이 일치하는지 확인한다.
- 옵션 입력칸·라벨·설명 위에서 휠을 사용할 때도 목록 경계가 유지되는지 확인한다.
- 수집·분석 및 채팅 분석 목록의 기존 휠 이동도 영향을 받는지 변경 범위에 맞춰 확인한다.
