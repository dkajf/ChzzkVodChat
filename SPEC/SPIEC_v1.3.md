### 각 구간별 요구 조건

1. API에서 받은 채팅을 메모리에 저장한 뒤, JSON 파일을 만들지 않고 바로 TXT를 생성한다.

별개로 json 저장은 설정에서 제어 가능 하도록 변경하여 txt 출력과 분리한다

 - 대화 참조

```

현재 v1.2.5 기준 코드를 보면 메모리에 저장한 뒤 TXT를 생성하고, JSON은 디스크에 잠깐 저장했다가 바로 삭제하는 방식입니다.

흐름을 순서대로 보면 다음과 같습니다.

API에서 채팅 50개씩 받아옴.
모든 채팅을 all_chats 리스트(메모리)에 저장.
수집이 끝나면 all_chats.sort() 수행.
save_chat_files(all_chats, ...) 호출.
여기서
all_chats → JSON 파일 저장
같은 all_chats → TXT 파일 저장

TXT 저장이 끝나면

json_path.unlink()

로 JSON 파일 삭제.

즉 실제 동작은

API
 ↓
메모리(all_chats)
 ↓
JSON 저장
 ↓
TXT 저장
 ↓
JSON 삭제

입니다.

그런데 JSON 저장이 사실 필요할까?

현재 구조에서는 필요 없습니다.

왜냐하면 TXT도 같은 all_chats 리스트를 그대로 사용해서 만들기 때문입니다.

현재는

all_chats
   ↓
json.dump(...)
   ↓
for chat in all_chats:
    TXT 작성

이라 JSON 파일을 다시 읽는 과정이 전혀 없습니다.

따라서 다음처럼 바꿀 수 있습니다.

API
 ↓
메모리(all_chats)
 ↓
TXT 생성
 ↓
끝

이렇게 하면

JSON 저장 I/O 제거
JSON 삭제 과정 제거
SSD 쓰기 감소
속도 약간 향상
코드도 더 단순해집니다.
개인적인 권장

이미 분석 모드도 TXT만 읽도록 변경되어 있으므로, v1.3에서는 JSON 생성 자체를 없애는 것이 가장 깔끔한 구조입니다.

즉 save_chat_files()를

메모리(all_chats)
      ↓
TXT 저장
      ↓
return txt_path

만 수행하도록 변경하면 됩니다. 이렇게 해도 현재 기능에는 영향이 없습니다.

```

이외에도 json -> txt 변경과 관련있는 함수, 변수들을 제거한다.

ex) load_chat_json(), json_path(), json_path_unlink() 등등

단 기능 구현 시 스스로 생각하여 더 효율적인 방식으로 수정할 수 있도록 한다

2. 설정 파일명과 내부 configformat 값도 버전과 연동되게 변경
 - 설정 파일명 양식을 다음과 같이 변경 ex) CVC_setting_v{program_version}.txt
 - 내부 ex) configformat = {program_version}
 - 버전 갱신시에는 기존 설정을 삭제하지 않고 남겨두는 방향으로

3. 설정에서 채팅 수집 모드 최대 수집 변경 옵션 제거
 - 최대 30개 채팅 수집 유지
설정 변경 관련 코드나 변수 최적화

4. 채팅 분석만 했을때 폴더를 새로 생성하지 않으니 폴더 생성변수따로 만들고 수집, 분석 둘 다 생성할 수 있도록 한다
 - 현재 1.2.5 버전은 채팅 분석을 따로 시도 할 경우 경로 폴더 생성이 안 됨 수정 필요

5. txt 파일을 window 창으로 드래그 시 출력되는 경로도 양식에 추가하여 인식할 수 있도록 변경

6. 분석 모드에서 분석 구간 입력시 시간 양식을 여유롭게 둘 수 있도록 한다
숫자 6개 입력시 ex) 012345 -> 01:23:45
숫자 4개 입력시 ex) 2222 -> 00:22:22
