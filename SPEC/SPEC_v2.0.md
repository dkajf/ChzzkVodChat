# ChzzkVodChat v2.0 Specification

작성일: 2026-11-10  

## 1. 버전 목표와 우선순위

v2.0의 최우선 목적은 기존 CLI 프로그램을 GUI로 전환하는 것이다. 기존 수집·분석 기능을 유지하면서 URL 입력부터 분석 결과 저장까지 한 흐름으로 실행한다.

| 우선순위 | 변경 목적 |
|---|---|
| 0 | GUI 전환: 입력, 설정, 진행 상태, 결과를 창에서 확인 |
| 1 | 수집·분석·출력 설정을 단일 설정으로 통합 |
| 2 | URL 입력 시 분석 옵션도 함께 입력하고 수집 후 필요하면 자동 분석. 기존 TXT용 별도 분석 탭 제공 |
| 3 | 분석 TXT 상단에 방송 정보 추가 |
~~| 4 | 수집 TXT에 당시 실제 시각을 함께 표시하는 옵션 추가 |~~
| 5 | 분석 단위를 1~10분으로 선택하고 VOD 시작 기준의 고정 경계에 정렬 |
| 6 | 경과 시간에 프리미어 입력 편의용 `:00`을 붙이는 표시 옵션 추가 |

아래의 세부 기본값·예외 정책 중 사용자 요청에 없던 내용은 **초안 제안**이다. 특히 12절 항목은 구현 전 검토한다. v1.3 코드 및 spec 상 기존 동작은 참고하되, 코드 구조와 구현 방식은 그대로 따르지 말 것.

## 2. GUI 구성

상단 탭은 **수집·분석 / 채팅 분석 / 옵션**으로 구성한다.

### 2.1 수집·분석 탭

- 본문은 영상별 항목 목록과 `[+] URL 입력칸`으로 구성한다. 추가 입력칸은 항상 목록 마지막에 유지한다.
- URL 입력 후 Enter 또는 `[+]` 버튼으로 영상별 항목을 생성한다.
- 추가 즉시 방송 정보를 비동기로 조회한다. 조회 중에도 다른 URL을 추가할 수 있다.
- 최대 10개이며 같은 VOD ID는 중복 추가하지 않고 안내한다. 현재 개수를 `3/10`처럼 표시한다.
- 중복·잘못된 URL은 각각 결과를 안내한다. 기존 목록은 유지한다.
- 10개 도달 시 추가 입력을 비활성화하고 항목 삭제 시 다시 활성화한다.
- 각 영상은 첫 줄 `[-] URL`, 다음 줄 방송 정보, 그 아래 `시작 시간 / 종료 시간 / 키워드` 입력칸으로 구성한다. 정보 조회 중에는 `정보 불러오는 중…`을 표시하고 조회 성공 후 분석 입력칸을 표시한다.
--
예시

[-] (URL)
    (정보)
    시작 시간:[  ] 종료 시간:[  ] 키워드:[  ]

[+] (URL 입력)
--
- `[-]` 클릭 시 영상과 개별 분석값을 함께 제거한다. 다른 영상의 입력은 유지한다.
- 조회 중 삭제된 항목의 늦은 응답은 무시한다. 같은 URL을 재추가해도 이전 응답을 새 항목에 적용하지 않는다.
- 항목별 채널명·제목·영상 길이를 지속 표시한다. 조회 실패 항목에는 오류와 재시도·삭제 버튼을 제공한다.
- 영상 길이는 `영상 길이: 08:20:00`으로 표시한다.
- **화면 하단**에 `채팅 수집 TXT 저장`, `채팅 분석 TXT 저장` 체크박스와 실행 버튼을 둔다. 별도의 3종 출력 선택 메뉴는 두지 않는다.
- 둘 다 체크하면 모두 출력, 하나만 체크하면 해당 TXT만 출력한다. 둘 다 해제하면 실행 버튼을 비활성화하고 이유를 표시한다.
- 분석 TXT만 체크하면 `채팅 수집 후 분석 결과만 저장합니다`를 표시한다.
- 시작·종료·키워드는 각 영상 아래에서 직접 편집한다. 분석 단위·TOP 개수·이동평균 등 나머지 공통 설정은 상단 옵션 탭에 둔다.
- 수집만 출력이면 영상별 분석 입력칸을 비활성화하고 분석 옵션을 적용·검증하지 않는다. 입력값은 유지하여 분석 저장 재선택 시 복원한다. 기존 TXT 분석 탭은 영향을 받지 않는다.
- 실행 전 준비 완료 항목과 옵션을 검증한다. 조회 실패·조회 중 항목은 실행 대상에서 제외됨을 명시한다. 실행 가능한 항목이 없으면 실행 불가다.
- 시작·종료·키워드는 영상별로 독립 적용하고 범위 오류도 해당 입력칸에 표시한다. 나머지 공통 옵션만 전체 영상에 동일 적용한다.
- URL 추가는 정보 조회까지만 수행한다. 하단 실행 버튼을 눌렀을 때 개별 입력값과 공통 옵션을 각 작업에 복사하여 수집·분석을 시작한다.

### 2.2 채팅 분석 탭

- 기존 채팅 TXT를 파일 선택으로 불러온다. 최초 버전은 단일 파일 분석을 기준으로 한다.
- 이 탭에도 선택한 TXT의 시작·종료·키워드 입력칸을 제공한다. 나머지 설정은 옵션 탭에서 가져오고 URL 분석과 같은 계산 로직을 사용한다.
- 새 형식과 기존 버전 TXT를 모두 지원한다.
- 방송 정보가 있으면 자동으로 읽으며, 없으면 미확인으로 표시한다.
- 재수집 없이 분석 TXT를 생성한다. 메인 화면 하단 출력 체크박스는 이 탭의 분석 실행에 영향을 주지 않는다.
- 같은 TXT를 다른 분석 옵션으로 재분석할 수 있다.

### 2.3 옵션 탭과 입력 편의

- 분석 단위, TOP 개수, 이동평균, 최소 채팅 수, 키워드 반복 제한, 병합 제한, 상세 로그, 시간 표시, 저장 위치 등 공통 옵션을 배치한다. 영상별 시작·종료·키워드는 이 탭에 중복 배치하지 않는다.
- 적용 버튼으로 공통 실행 설정에 반영하고, 기본값 저장 버튼으로 재실행 후 사용할 기본값을 저장한다. 적용하지 않은 공통 편집값으로 실행하지 않는다.
- 취소는 적용 전 공통 편집을 취소한다. 기본값 복원은 확인 후 적용한다.
- 영상별 입력값은 해당 항목에서 즉시 반영하며 공통 옵션의 적용 버튼을 추가로 누를 필요가 없다.
- 새 영상의 시작은 실제 값 `00:00:00`, 키워드는 실제 값 `ㅋ`로 초기화한다. 저장된 기본 키워드가 있으면 이를 우선하고 다른 영상의 편집값은 복사하지 않는다.
- 종료는 영상별 조회한 영상 길이를 종료 칸에 실제 값으로 채운다. 클릭하여 직접 값을 편집할 수 있다.
- 종료 칸에는 플레이스홀더 방식을 통한 영상 끝 시간 안내를 유지하여 수정 후에도 원래 길이와 비교할 수 있게 한다.
- 다른 URL 추가나 정보 재조회가 직접 편집한 값 또는 다른 영상 값을 덮어쓰지 않는다. 자동 끝 모드의 종료 값만 해당 영상 길이에 맞춰 갱신한다.
- 길이를 알 수 없으면 `영상 끝: 미확인`으로 표시한다. 자동 모드는 유지하되 0초나 마지막 채팅 시각을 실제 영상 길이로 채우지 않는다. 범위 산출은 7.2절을 따른다.
- TXT 분석도 같은 입력 동작을 사용한다. 메타데이터 길이가 없으면 `채팅 데이터 끝까지`라고 구분한다.
- 시작·키워드를 지워둔 경우 각각 0·ㅋ를 적용한다는 안내를 칸 아래 표시하고 실행 요약에도 적용값을 표시한다. 종료는 직접 지정 모드에서 비워두면 자동으로 영상 종료 시간으로 채운다.
- 입력칸 라벨은 항상 표시한다. 각 칸에 마우스를 올리면 형식·허용 범위·기본값·빈칸 동작을 툴팁으로 간략히 안내한다. 키보드 포커스에서도 같은 설명에 접근할 수 있게 한다.
- 키워드 툴팁의 최대 글자 수는 1.3 코드와 SPEC의 실제 제한 확인 후 정확한 수치로 표기한다. 임의로 제한을 바꾸지 않는다.

### 2.4 진행 및 결과 영역

- VOD별 상태: 대기 → 정보 조회 → 수집 → 분석 → 저장 → 완료 / 실패 / 취소.
- 현재 VOD, 수집 개수, 처리 위치, 분석·저장 상태, 오류 원인을 표시한다.
- 전체 채팅 개수를 알 수 없으면 채팅 개수 기반 백분율을 만들지 않는다. 진행률은 VOD 시간 기준임을 표시하거나 불확정 상태로 표시한다.
- 완료한 결과 파일 및 폴더를 열 수 있다.
- 작업 중에도 창 이동·갱신 등 GUI가 응답해야 한다.
- 실행 시 옵션을 작업에 복사하여, 실행 중 설정 변경이 이미 시작한 작업에 영향을 주지 않게 한다.
- 중복 실행 버튼 입력으로 같은 작업을 두 번 시작하지 않는다.

## 3. 통합 실행과 출력 정책

**출력 모드는 저장할 결과물의 종류다. 분석만 출력해도 URL의 채팅 데이터 수집은 필요하다.**

| 입력 / 출력 모드 | 채팅 수집 처리 | 분석 처리 | 수집 TXT | 분석 TXT |
|---|---|---|---|---|
| URL / 수집만 출력 | 실행 | 생략 | 저장 | 저장 안 함 |
| URL / 분석만 출력 | 실행 | 실행 | 저장 안 함 | 저장 |
| URL / 모두 출력 | 실행 | 실행 | 저장 | 저장 |
| 기존 TXT / 채팅 분석 탭 | 재수집 없음 | 실행 | 원본 유지 | 저장 |

- 수집 결과를 공통 내부 데이터로 분석에 전달한다. 자동 분석 때문에 저장된 TXT를 다시 읽을 필요는 없다.
- 분석만 출력 시 임시 수집 데이터를 내부적으로 사용할 수 있지만 사용자 결과물로 수집 TXT를 남기지 않는다.
- 모두 출력에서 수집 TXT 저장 후 분석이 실패하면 수집 결과는 유지하고 분석 실패를 별도로 안내한다.
- 다중 URL 중 한 항목의 실패는 다른 항목의 실행을 막지 않는다.
- 수집이 불완전하게 종료되면 정상 완료 분석 결과로 표시하지 않는다. 자동 분석은 생략하고 실패·취소 상태를 표시한다.
- 취소 시 새 작업을 시작하지 않고 현재 처리를 안전하게 중단한다. 완료한 파일은 유지하고 미완성 파일은 정상 결과 이름으로 남기지 않는다.

## 4. 단일 설정 파일

단일 파일의 제안 이름은 `CVC_settings.json`이다. 파일명은 고정하고 내부 `schema_version`으로 구조를 관리한다. GUI는 설정을 편집하는 화면이며, 실행 파일 내부에 사용자 설정을 저장한다는 의미는 아니다.

| 분류 | 항목 | 초안 기준 |
|---|---|---|
| 출력 | 하단 TXT 저장 체크박스 기본값 | 둘 다 체크 |
| 출력 | 저장 위치 | 사용자 쓰기 가능한 위치 선택 가능 |
| 출력 | 기존 파일 처리 | 덮어쓰기 확인 / 새 이름 저장. 기본은 새 이름 |
| 시간 | 수집 TXT 실제 시각 표시 | 기본 끔 |
| 시간 | 경과 시간 형식 | 기본 `HH:MM:SS`, 선택 `HH:MM:SS:00` |
| 분석 | 키워드 | 기본 `ㅋ` |
| 분석 | 분석 구간 단위 | 1~10분 정수 선택, 기본 1분 |
| 분석 | TOP 개수 | 기본 10, 양의 정수 |
| 분석 | 이동평균 창 | 이전 N분. 분석 단위의 양의 정수 배수 (7.3절 제안 기준) |
| 분석 | 최소 채팅 수 | 0=분석 범위의 구간당 평균, 양의 정수=직접 지정 |
| 분석 | 채팅당 키워드 반복 제한 | 기본 5, 0=무제한 |
| 분석 | 최대 병합 구간 수 | 기본 3개, 0=무제한 (7.3절 제안 기준) |
| 분석 | 상세 로그 저장 | 기존 기본값 확인 후 유지 |

- 설정 파일에는 공통 기본값과 기본 키워드를 저장한다. 영상별 입력값·조회한 종료 시각은 작업 상태이며 다른 영상의 기본값으로 저장하지 않는다.
- 최초 실행 시 기본값으로 생성하고, 재실행 시 마지막으로 저장한 설정을 복원한다.
- 설정 저장은 임시 파일 작성 후 교체하여 중간 종료에 따른 손상을 줄인다.
- 누락 항목은 기본값으로 보완한다. 유효하지 않은 항목은 해당 항목만 복원하고 안내한다.
- 손상된 파일은 백업 후 기본값으로 복구한다. 버전 번호가 다르다는 이유만으로 전체 설정을 삭제하지 않는다.
- 구버전 설정은 실제 파일 구조를 확인해 변환 가능한 항목을 이관하고 원본을 보존한다. 매핑하지 못한 항목은 안내한다.
- 설정 경로는 구현 시 확정하되 실행 파일 폴더가 쓰기 금지여도 프로그램이 실행되어야 한다.
- 복수 창 실행 시 작업 데이터는 분리한다. 설정 파일 동시 저장은 원자적으로 처리하며, 마지막 저장이 적용됨을 기준으로 한다.

## 5. 방송 정보와 TXT 호환성

### 5.1 공통 방송 정보

수집 데이터에 다음 메타데이터를 보관한다. 분석 TXT 상단에는 반드시 정보 영역을 출력한다.

- 채널명, 방송 제목, VOD ID, VOD URL
- 실제 방송 시작 시각 및 시간대
- 전체 방송 길이
- 방송 종료 시각: 출처가 있을 때만 기록. 시작+길이로 산출했다면 계산값임을 표시
- 분석 범위, 분석 대상 채팅 수, 적용한 주요 분석 옵션

예시의 값은 형식 설명용이다.

```text
[방송 정보]
채널: 예시 채널
제목: 예시 방송 제목
VOD ID: 12345678
VOD URL: https://chzzk.naver.com/video/12345678
방송 시작: 2026-11-10 12:00:00 (KST)
전체 방송 길이: 08:20:00
분석 범위: 01:00:00 ~ 03:00:00 (종료 제외)
분석 구간 단위: 1분
분석 대상 채팅 수: 12,345
시간 표시: HH:MM:SS
```

- 정보 조회 실패 시 `미확인`으로 표기한다. 파일 생성 시각·업로드 시각을 방송 시작 시각으로 대체하지 않는다.
- 기존 TXT에서 제목·전체 길이를 알 수 없다면 임의로 추정하여 확정 정보처럼 표시하지 않는다.
- 마지막 채팅 시각은 전체 방송 길이가 아니다. 범위 산출에 사용하면 `채팅 데이터 기준 범위`라고 구분한다.

### 5.2 새 수집 TXT

- 방송 정보 헤더를 포함한다. 헤더 구간과 채팅 행을 구분하여 분석기가 헤더를 채팅으로 읽지 않게 한다.
- 실제 시각 옵션과 경과 시간 형식이 달라도 동일한 분석기로 읽을 수 있어야 한다.
- 메타데이터가 없는 구버전 TXT도 계속 분석 가능해야 한다.
- UTF-8로 저장하며 한글·이모지·특수문자를 보존한다.
- 닉네임 조회 실패 시 `Unknown`을 사용하고 채팅 자체는 보존한다.

## 7. 분석 단위 1~10분과 구간 정렬

### 7.1 확정 요구사항

- 옵션 탭에서 분석 구간 단위를 1~10분 정수로 선택한다. 기본 1분이다.
- 모든 구간은 **VOD 경과 시간 00:00:00을 기준으로 선택한 분 간격**에 정렬한다. 첫 채팅이나 사용자 분석 시작 시각을 기준으로 이동시키지 않는다.
- 3분은 00~03, 03~06, 06~09분, 10분은 00~10, 10~20분으로 나눈다. 시간이 바뀌어도 VOD 시작부터 연속 계산한다.
- 모든 경계의 초는 00이다. 내부 집계 정밀도는 원본을 유지한다.

```text
bucket_ms = analysis_interval_minutes * 60000
bucket_index = floor(vod_elapsed_ms / bucket_ms)
bucket_start_ms = bucket_index * bucket_ms
bucket_end_ms = bucket_start_ms + bucket_ms
```

구간은 `[시작, 종료)`로 계산한다. 시작 포함, 종료 제외다.

| 단위 | 채팅 경과 시간 | 포함 구간 |
|---|---|---|
| 1분 | 00:00:59.999 | 00:00:00 ~ 00:01:00 |
| 1분 | 00:01:00 | 00:01:00 ~ 00:02:00 |
| 3분 | 00:02:59.999 | 00:00:00 ~ 00:03:00 |
| 3분 | 00:03:00 | 00:03:00 ~ 00:06:00 |
| 10분 | 01:23:50 | 01:20:00 ~ 01:30:00 |

### 7.2 부분 범위와 마지막 구간

- 분석 범위는 `[시작, 종료)`다. 시작=종료는 실행 전 오류다.
- 1분 단위로 `00:10:10 ~ 00:12:50`을 분석하면 라벨은 10:00, 11:00, 12:00이고 범위 안 채팅만 집계한다.
- 5분 단위로 같은 범위를 분석하면 라벨은 10:00 한 개이고 실제 포함 범위는 10:10~12:50이다.
- 집계 구간과 실제 포함 범위를 별도 보관하고 처음·끝의 부분 구간임을 표시한다. TOP·병합 결과의 유효 시간은 요청 범위를 넘지 않는다.
- 무채팅 구간도 0으로 생성한다. 범위와 겹치지 않는 구간은 생성하지 않는다.
- 자동 전체 분석에서 길이를 모르면 마지막 채팅을 포함하는 선택 단위 구간의 끝을 내부 종료 경계로 사용하고 데이터 기준임을 표시한다. 채팅이 전혀 없고 길이도 없으면 범위 산출 불가로 안내한다.
- 자동 끝까지 분석에서 마지막 채팅이 알려진 VOD 길이와 같으면 마지막 유효 구간에 포함한다. 길이가 구간 경계와 같아도 끝점만을 위한 추가 구간을 만들지 않는다. 사용자가 직접 지정한 종료는 제외한다.

### 7.3 통계·이동평균·병합의 연동 정책 (검토 제안) - 제안 확인 완료

분석 단위 선택은 확정 요구다. 아래 연동 정책은 구현자가 임의 선택하지 않도록 제안안을 명시한 것이며 최종 검토 대상이다.

- 부분 구간도 1개 구간으로 집계하고 분당 환산하지 않는다. 결과는 `5분당 채팅 수` 등 적용 단위로 표시한다.
- 최소 채팅 수 0은 전체 분석 구간의 채팅 수 평균이다. 0개 채팅 구간과 부분 구간도 포함하고 비교 전 반올림하지 않는다.
- 이동평균 입력은 `이전 N분`을 유지하되 N은 분석 단위의 양의 정수 배수로 제한한다. 5분 단위·15분 창은 현재 구간을 제외한 이전 3개 구간을 사용한다.
- 분석 단위 변경으로 N이 유효하지 않으면 오류와 유효값 예시를 표시한다. 임의로 올림하거나 변경하지 않는다. 설정 이관 시에도 자동 변환 대신 안내한다.
- 초기에는 존재하는 이전 구간만 사용한다. 이전 구간 없음·평균 0은 증가율 `N/A`, 증가율 TOP 제외를 제안한다. 기존 동작과 비교 후 확정한다.
- 병합 제한은 `최대 병합 구간 수`로 표시한다. 기본 3개, 0=무제한이다. 5분×3개면 최대 15분이며 실제 시간도 함께 안내한다.
- 연속 구간은 bucket_index 차이가 1인 구간이다. 기존 minute+1 판정을 그대로 사용하지 않는다.
- 분석 TXT 상단에 분석 단위, 이동평균 창(분과 구간 수), 병합 제한(구간 수와 분), 최소 컷 적용값을 기록한다.
- 구버전 병합 제한은 1분 단위에서 같은 숫자로 이관하면 의미가 유지된다. 단위 변경 시 실제 병합 시간이 바뀜을 표시한다.
- 내부 계산은 숫자 시간과 구간 인덱스를 사용하고 출력 시에만 문자열로 변환한다.

## 8. 프리미어용 경과 시간 표시

설정 이름 제안: `프리미어 입력용 시간 표시(:00 추가)`

| 기본 표시 | 옵션 사용 |
|---|---|
| 01:23:45 | 01:23:45:00 |
| 00:10:00 ~ 00:12:00 | 00:10:00:00 ~ 00:12:00:00 |

- 마지막 필드는 프레임 자리다. v2.0에서는 실제 프레임을 계산하지 않고 항상 `00`을 붙인다.
- API의 FPS 정보 유무와 관계없이 동작하는 출력 편의 옵션이다.
- 수집 TXT의 VOD 경과 시간, 분석 TXT의 분석 범위·TOP·상세 로그, GUI 결과의 경과 시간 복사에 동일하게 적용한다.
- 방송 날짜·실제 시각에는 적용하지 않는다. 방송 길이와 같은 지속시간 표기는 `HH:MM:SS`를 유지한다.
- 분석 입력은 기존 `HH:MM:SS`를 사용하고 이 옵션 때문에 입력 형식을 바꾸지 않는다. 출력 TXT의 `HH:MM:SS:00`은 분석기가 읽을 수 있어야 한다.
- 초 미만 값은 출력 시 버림하되 집계에는 원본 정밀도를 유지한다.
- 시퀀스 FPS·시작 타임코드·드롭 프레임을 반영한 변환 기능은 범위에 포함하지 않는다. 실제 프리미어에서 복사·붙여넣기는 수동 검증한다.

## 9. 기존 분석 기능 유지

- 채팅량 / 이동평균 대비 증가율 / 키워드 개수 / 키워드 포함 채팅 비율의 TOP을 유지한다.
- 키워드 개수와 키워드 포함 채팅 수는 구분한다. 비율은 포함 채팅 수 ÷ 전체 채팅 수다. 채팅 0개 구간은 비율 0으로 처리한다.
- 채팅당 키워드 반복 제한, 최소 채팅 수, TOP 개수, 인접 구간 병합 제한, 상세 로그 설정을 유지한다.
- 후보 확보·병합·보충 및 병합 후 순위 산정은 기존 코드를 확인하여 문서화하고 유지한다. TOP 개수는 가능한 결과가 있을 때만 채운다.
- 병합은 선택한 분석 단위의 연속 구간만 대상으로 하며 모든 TOP에 같은 인접 판정과 길이 제한을 적용한다.
- 각 TOP은 해당 지표 내림차순, 동률은 시간 오름차순이다. 키워드 비율 동률은 키워드 개수 내림차순 후 시간 오름차순이다.
- 병합 내부 상세 행은 시간순으로 표시한다.
- 키워드 없음 / 채팅 없음 / TOP 대상 없음은 오류 종료 대신 해당 상태를 표시한다.
- 수집 최초·최종 페이지, 같은 시각의 서로 다른 채팅, 재조회 중복 처리에 관한 기존 무결성을 유지한다. 같은 시각이라는 이유만으로 중복 제거하지 않는다.

## 10. 입력·파일·오류 정책

- 잘못된 URL, 빈 입력, 10개 초과, 읽을 수 없는 TXT, 잘못된 설정은 필드 근처에서 원인을 안내한다.
- 분석 범위는 음수 불가, 분·초는 0~59, 시간은 24 이상 허용한다. 방송 길이를 알 때 범위 초과는 오류로 안내한다.
- 시작 생략은 0이다. 종료는 영상별 자동 끝 모드에서 자동 산출하고, 직접 지정 모드에서는 명시적 입력을 요구한다. 키워드 생략은 ㅋ이며 실제 적용값을 안내한다.
- 숫자만 입력하는 기존 시간 형식은 기존 파서 규칙을 확인하고 예시를 GUI에 제공한다. 임의의 새 해석을 추가하지 않는다.
- 네트워크/API 재시도는 횟수를 제한하고 최종 실패 원인을 표시한다. 무한 재시도하지 않는다.
- 파일 이름에 사용할 수 없는 문자는 치환하고 수집·분석 파일 이름을 구분한다. 기본명은 기존 날짜_VOD번호 규칙을 유지한다.
- 저장 위치 쓰기 실패, 디스크 부족, 기존 파일 충돌을 안내한다. 사용자 선택 없이 기존 파일을 덮어쓰지 않는다.
- 새 TXT 파서는 닉네임·채팅 안의 대괄호·콜론을 시간이나 헤더로 오인하지 않아야 한다.
- 진행 중 창 닫기는 작업 중임을 안내하고 종료 또는 계속 실행을 선택하게 한다.

## 12. 구현 전 사용자 확인 및 코드 조사

### 최종 검토할 제안 정책 - 검토 완료

1. 기본 출력 모드는 **모두 출력**으로 한다.
2. 설정 파일은 **고정 파일명 + 내부 스키마 버전**으로 관리한다.
3. 실제 시각 표시 기본값은 끔, 프리미어 시간 표시 기본값도 끔으로 한다.
4. 분석 시작·끝이 분 중간이면 입력 범위는 유지하고 구간은 VOD 시작 기준 선택 간격에 맞춘다. 부분 구간도 1개로 집계한다.
5. 이동평균 계산 불가 또는 평균 0은 `N/A`로 표시하고 증가율 TOP에서 제외한다.
6. 기존 결과와 파일명이 충돌하면 기본은 새 이름으로 저장한다.
7. 이동평균은 이전 N분을 유지하고 분석 단위의 배수만 허용한다. 병합 제한은 분이 아닌 최대 구간 수(기본 3개)로 바꾼다. 이 두 항목은 대화에서 제안한 정책이며 명시적인 개별 확정은 아직 없다.

### 1.3 참고 자료와 구현 우선순위

- 구현 시 1.3 코드와 1.3 SPEC을 함께 제공한다. 가능하면 실제 설정 파일, 수집 TXT, 분석 TXT 예시도 각 1개 제공한다.
- 변경 요구는 검토 완료한 2.0 SPEC을 우선한다. 변경 대상으로 명시하지 않은 기존 기능은 유지한다.
- 기존 코드는 현재 동작의 근거, 1.3 SPEC은 의도한 동작과 회귀 확인의 근거다. 코드와 SPEC의 불일치를 버그인지 요구 변경인지 임의 판단하지 않는다.
- 구현 전 기존 구조·파일 형식·설정·계산 로직을 조사하고 충돌 및 제안 정책을 정리한다. 확인되지 않은 내용을 기존 동작으로 단정하지 않는다.

### 구현 담당자가 기존 코드/API에서 확인할 사항

- GUI 프레임워크, 배포 방식, 기존 설정 실제 구조·기본값·이관 규칙.
- 방송 시작 시각·방송 길이·개별 채팅 실제 타임스탬프의 제공 여부와 정확한 의미.
- VOD 타임라인과 실제 방송 시간의 일치 여부 및 계산 가능 조건.
- 기존 TXT 형식, 숫자형 시간 입력 규칙, 기존 분석 산식과 병합 후 점수 계산.
- 기존 수집 중복 제거 방식 및 시간 단위.

확인되지 않은 API 필드명이나 GUI 프레임워크를 이 문서만으로 확정하지 않는다. 조사 결과가 요구사항과 충돌하면 구현 전에 해당 항목을 보고하고 확정한다.

## 13. 이번 버전의 범위

GUI 전환, 통합 처리, 입력 UX 및 분석 단위 선택을 우선 완료한다. 그래프 대시보드, 다중 키워드, 드래그 앤 드롭, 중단 지점 이어받기, 실제 프레임 단위 변환은 별도 요청 전까지 필수 범위에 추가하지 않는다.
